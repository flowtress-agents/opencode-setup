# ADR FormatADRs in `docs/adr/`, sequential: `0001-slug.md`, `0002-slug.md`, etc.Create `docs/adr/` lazily ÔÇö first ADR only.## Template```md# {Short title of the decision}{1-3 sentences: what's the context, what did we decide, and why.}```Single paragraph OK. Value = record *that* decision made + *why* ÔÇö not filling sections.## Optional sectionsOnly when genuine value. Most ADRs won't need:- **Status** frontmatter (`proposed | accepted | deprecated | superseded by ADR-NNNN`) ÔÇö when decisions revisited- **Considered Options** ÔÇö rejected alternatives worth remembering- **Consequences** ÔÇö non-obvious downstream effects## NumberingScan `docs/adr/` for highest number, increment.## When to offer an ADRAll three true:1. **Hard to reverse** ÔÇö changing mind later costs meaningful effort2. **Surprising without context** ÔÇö future reader wonders "why this way?"3. **Real trade-off** ÔÇö genuine alternatives, picked one for specific reasonsEasy to reverse ÔåÆ skip (reverse). Not surprising ÔåÆ nobody wonders. No real alternative ÔåÆ obvious thing, nothing to record.### What qualifies- **Architectural shape.** Monorepo. Event-sourced write model, Postgres read projection.- **Integration patterns between contexts.** Ordering Ôåö Billing via domain events, not sync HTTP.- **Technology with lock-in.** DB, bus, auth, deploy target ÔÇö not every library; ones that take quarter to swap.- **Boundary and scope.** Customer context owns customer data; others reference by ID. Explicit no-s as valuable as yes-s.- **Deliberate non-obvious path.** Manual SQL not ORM because X. Stops next engineer "fixing" deliberate choice.- **Constraints not in code.** No AWS (compliance). <200ms (partner API contract).- **Rejected alternatives when rejection non-obvious.** GraphQL considered, REST for subtle reasons ÔÇö else GraphQL resuggested in six months.
