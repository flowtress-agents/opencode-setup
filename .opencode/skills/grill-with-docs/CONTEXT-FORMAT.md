# CONTEXT.md Format## Structure```md# {Context Name}{One or two sentence description of what this context is and why it exists.}## Language**Order**:{A one or two sentence description of the term}_Avoid_: Purchase, transaction**Invoice**:A request for payment sent to a customer after delivery._Avoid_: Bill, payment request**Customer**:A person or organization that places orders._Avoid_: Client, buyer, account```## Rules- **Opinionated.** Multiple words for same concept ÔåÆ pick best, list others under `_Avoid_`.- **Tight definitions.** 1-2 sentences. What it IS, not what it does.- **Project-context terms only.** General programming concepts (timeouts, error types, utilities) don't belong even if used heavily. Ask: unique to this context or general? Former only.- **Subheadings** when natural clusters. Single cohesive area ÔåÆ flat list OK.## Single vs multi-context repos**Single context (most repos):** One `CONTEXT.md` at repo root.**Multiple contexts:** `CONTEXT-MAP.md` at root lists contexts, locations, relations:```md# Context Map## Contexts- [Ordering](./src/ordering/CONTEXT.md) ÔÇö receives and tracks customer orders- [Billing](./src/billing/CONTEXT.md) ÔÇö generates invoices and processes payments- [Fulfillment](./src/fulfillment/CONTEXT.md) ÔÇö manages warehouse picking and shipping## Relationships- **Ordering ÔåÆ Fulfillment**: Ordering emits `OrderPlaced` events; Fulfillment consumes them to start picking- **Fulfillment ÔåÆ Billing**: Fulfillment emits `ShipmentDispatched` events; Billing consumes them to generate invoices- **Ordering Ôåö Billing**: Shared types for `CustomerId` and `Money````Skill infers structure:- `CONTEXT-MAP.md` exists ÔåÆ read map, find contexts- Only root `CONTEXT.md` ÔåÆ single context- Neither ÔåÆ create root `CONTEXT.md` lazily on first resolved termMultiple contexts: infer which topic relates to. Unclear ÔåÆ ask.
